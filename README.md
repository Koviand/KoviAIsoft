## Идея

**KoviAIsoft** — это desktop-приложение, в котором встречаются привычный локальный чат в духе LM Studio и агент, который умеет работать с проектом: читать и писать файлы, запускать команды, искать по коду.

Всё крутится у вас на машине. Модель загружается в память через **llama.cpp**, ответы стримятся в чат, а опасные действия агента проходят через подтверждение.

> Setup EXE → установили → ярлык → скачали GGUF → работаете.  
> Или portable-папка → скопировали на ПК → запустили EXE.

Установка и сборка из исходников: **[INSTALL.md](INSTALL.md)** (`pnpm pack` → `release\KoviAIsoft-Setup-*.exe`).

## Почему KoviAIsoft, а не «просто чат с GGUF»

Большинство локальных клиентов умеют **говорить с моделью**. KoviAIsoft заточен на другое: **сделать работу в вашем проекте на Windows** — с планом, инструментами, подтверждениями и без облачной подписки.

| | LM Studio / подобные чаты | Ollama + веб-UI | Cursor / облачные агенты | **KoviAIsoft** |
|--|---------------------------|-----------------|---------------------------|----------------|
| Локальные GGUF | да | да (свой runtime) | обычно нет / через API | **да, llama.cpp + автопод железо** |
| Агент с файлами и shell | слабо / плагины | обычно нет | да | **да, встроенный plan→tools** |
| Код остаётся на ПК | да | да | часто уходит в облако | **да, чат офлайн** |
| Под Windows «из коробки» | ок | часто через CLI | ок | **Setup EXE + portable + cmd** |
| Подтверждение опасных действий | редко | редко | по политике IDE | **diff / confirm / таймаут** |
| Цена за агента | бесплатно (только железо) | бесплатно | подписка | **бесплатно (только железо)** |

### Конкретные преимущества

1. **Чат + агент в одном окне**  
   Не нужно отдельно «чат для вопросов» и IDE-агент для правок. Обычный диалог и `@agent` / автодетект задач живут в одном composer: спросили — ответили; попросили «добавь экран» — пошёл план и `write_file`.

2. **Cursor-like цикл без облака**  
   План с kinds (`explore` → `edit` → `run` → `verify` → `finalize`), исполнение по шагам, soft-skip застрявших пунктов, resume после Stop/бюджета. Модель работает у вас в VRAM, а не на чужом сервере.

3. **Модели «подтягиваются» под программу, а не наоборот**  
   Семейство и размер GGUF влияют на JSON/constraints (Qwen, Llama, DeepSeek, LFM, tiny…). Маленькие модели не крутят отказ вечно: soft-stop и подсказка сменить на ≥7B. Runtime сам выбирает CUDA / Vulkan / CPU.

4. **Железо и загрузка без шаманства**  
   Оценка VRAM/RAM, профили ngl/context, «Под этот ПК», монитор tok/s и заполнения контекста. Portable: скопировали папку — уже с HF CLI внутри.

5. **Безопасность, заточенная под локальный агент**  
   Доступ к диску ограничен корнем проекта; shell не уводит `cd` наружу; браузер режет SSRF; мутации — через подтверждение с превью. Это не «дайте модели полный ПК», а рабочий контур с ручным контролем риска (Ask / Auto-safe / Full).

6. **Windows — first-class, не afterthought**  
   Адаптация команд под `cmd`, понятные пути, portable без установки стека. Рассчитано на разработчика, который реально сидит на Windows, а не «потом как-нибудь под WSL».

7. **Рабочая память и длинные прогоны**  
   При сжатии истории сохраняются цель, план и затронутые файлы. Бюджет шагов, auto-extend и «Продолжить» — чтобы агент не обрывался на полуслове из‑за лимита UI.

**Коротко:** если нужен только «поговорить с Llama» — хватит LM Studio. Если нужен **локальный агент, который пишет код в ваш репозиторий на Windows без подписки** — это зона KoviAIsoft.

## Кому подойдёт

- Хотите **сильную локальную модель** без подписки и без отправки кода в чужой API  
- Нужен не только чат, а **помощь с файлами и командами** на Windows  
- Цените **контроль**: папка проекта, корни моделей, режимы Ask / Auto-safe / Full  
- Удобнее возить приложение **флешкой / папкой**, чем ставить стек вручную  
- Смотрите в сторону Cursor-like агента, но хотите **оставить модели и данные у себя**

## Возможности

### Runtime под ваше железо

Приложение само смотрит на систему и ставит подходящий билд **llama.cpp** — CUDA, Vulkan или CPU. Поддерживаются современные архитектуры (в том числе вроде LFM3). Runtime можно обновлять тихо в фоне. Отдельный **монитор** показывает VRAM, скорость генерации и заполнение контекста.

### Модели без ручной возни

- Сканирование локальных `.gguf` и оценка «влезет / медленно / не пойдёт»  
- Рекомендации квантов под ваш VRAM и RAM  
- Скачивание с **Hugging Face** — в portable уже есть встроенный HF CLI  
- Своя папка загрузки, проверка GGUF, удаление модели с диска  
- Профили загрузки: баланс, мало VRAM, только CPU, автоподбор под ПК  

### Чат, который держит нить

Стриминг, температура и контекст, system prompt. Длинные диалоги сжимаются аккуратно: цель, план и затронутые файлы не выкидываются вместе с «хвостом» истории — working memory помогает модели не терять задачу.

### Агент для реальной работы

```mermaid
flowchart LR
  You[Вы в чате] --> Intent{Нужны действия?}
  Intent -->|нет| Chat[Обычный ответ]
  Intent -->|да / @agent| Loop[План и tool-loop]
  Loop --> Tools[Файлы · терминал · поиск · браузер · MCP]
  Tools --> Confirm{Риск?}
  Confirm -->|да| UI[Подтверждение]
  Confirm -->|нет| Done[Результат в проекте]
  UI --> Done
```

- План шагов и timeline процесса в UI  
- Инструменты: файлы, патчи, поиск, терминал (с адаптацией под Windows), веб, Playwright, MCP  
- `@agent …` или автоопределение coding/tool-задач  
- Для задач «напиши / реализуй» агент дожимает запись файлов, а не уходит в пустой текст  
- Подтверждения с превью diff и таймаутом, если диалог забыли  

### Безопасность по умолчанию

Доступ ограничен **папкой проекта** и каталогами моделей. Shell не уводит `cd` за пределы разрешённых корней; браузер режет SSRF, в том числе через redirect. Junctions и опасные системные пути учитываются. Сеть нужна для загрузки моделей/runtime и опциональных web-инструментов — сам чат с локальной моделью работает офлайн.

### Интерфейс

Первый запуск с онбордингом, несколько цветовых тем, единый чат для диалога и агента, настройки MCP и доступа к файлам — без отдельного «режима агента» в навигации.

## Как это выглядит в работе

1. **Runtime** — поставить llama.cpp под ваше железо.  
2. **Модели** — выбрать папку, скачать или указать GGUF, **загрузить в память**.  
3. **Настройки** — корень проекта (удобно положить туда `AGENTS.md`).  
4. **Чат** — обычные вопросы текстом; код и правки — через `@agent`.  
5. **Монитор** — следить за VRAM и tok/s во время длинных прогонов.  

Остановить генерацию можно кнопкой **Stop**.
